2\. 最重要的問題與原因

核心問題：網站的「行銷 / 轉換層」從來沒有被建出來，而它是整個首頁漏斗的終點。

\- 首頁精心排了一條訪客決策路徑，但路徑盡頭的兩個動作（免費體驗 / 訂閱會員）都是 placeholder，程式碼註解直接寫「Payment destination out of scope」。

\- 結果：訪客理解了需求、理解了 JOTI、理解了產品，然後點「訂閱會員」→ 落在一個沒有價格、沒有方案、沒有 Trial 說明的登入頁。四個已定案的產品決策（Trial 30d/30h、NT$333、NT$3,333、trial 不立即扣款）在網站上完全隱形。 這是最大的 conversion friction，且其他漏斗優化都依賴「訂閱資訊先存在」。

次要根因（造成「看起來壞掉 / 未完成」的觀感）：

1\. 沒有被強制共用的卡片 / 連結樣式規範 → 同一個「未套樣式的藍色連結」bug 打中 3 個元件，Foundation / Practice 修好了，Module Library 漏掉、仍上線（M1）。

2\. 內容渲染走捷徑 → Module 詳細頁直接 \<ReactMarkdown> 整份 .md，Foundation 頁的過濾方案（toLessonContent()）從未一般化到 Module（M4）。

3\. responsive 與狀態設計只在特定 sprint 碰過的地方做完整（Practice Builder、About 頁有真斷點與狀態分支），「靜態」頁面只拿到最低限度（M6、W10）。

4\. 兩套 CSS 疊在一起沒有收斂（index.css / App.css）→ dark mode 半壞、視覺語言不一致（W3）。

3\. 建議的 refinement 順序

1\. 先修「看起來壞掉 / 誤導」的基本盤（小、便宜、直接影響信任）：M1（Module Library 樣式）、W3（logo 底線 + 收斂成一套設計系統的最小步）、M5（404 頁）、W4（時長格式統一）。

2\. 讓產品變得看得懂：M3 / M2 —— 做一個真實的 Pricing / Plan 區塊或頁（即使是靜態），明確寫出 Trial（30 天或 30 module-hours 先到）、Monthly NT$333、Annual NT$3,333、「Trial 期間訂閱不立即扣款、Trial 結束才首次扣款」，並把 Hero / Final CTA 的「訂閱會員」指向它。這是最大的 conversion 槓桿，漏斗其他優化都建立在它存在之上。

3\. 清理內容表面：M4（Module 詳細頁比照 Foundation 過濾 .md）、W5（中文 h1）、W9（prerequisite 呈現）、W1（Hero 文案順序）、N7。

首選：Pricing / Plan 區塊 + 接上 CTA（對應 M2 + M3）

做什麼：一個表達方案的頁面或首頁區塊（/pricing 或 Home 內一個 section），內容全部來自已定案的產品決策：

\- 取消：付費期間結束前仍保有使用權；續扣失敗：帳號保留、期末失去會員權限。

\- 它解鎖首頁那條已經排好的漏斗；不做這個，其他所有首頁優化的效益上限都很低。
